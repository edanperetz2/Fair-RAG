\noindent\textbf{This is a working diagnostic document, not part of the paper.}
Below are exact recreations of the paper's Table~2 (\texttt{tab:hybrid}), Table~3
(\texttt{tab:baseline}, Appendix A), and Table~4 (\texttt{tab:hybrid-full}, Appendix
B) --- same rows, same columns, same PL($\alpha$) matches, same
EU$_{\text{norm}}$/$\Delta$EU/significance stars (all untouched, still from the real
$N{=}10$ generation runs) --- with EE-D recomputed at $N{=}100$ reranking samples.
For Tables 2 and 4 this is a direct per-cell swap (EE-D only depends on reranking
output, not on which lists were sent to the LLM). Table 3 is different: since it
bins each \emph{query} by its own EE-D, this required recomputing per-query EE-D at
$N{=}100$ and re-binning, not just swapping a cell mean --- see \S3 for detail.
Re-matching each cell's PL $\alpha$ using $N{=}100$ estimates (rather than reusing
the $N{=}10$-matched $\alpha{=}2$) was also checked: it does not change any of the
28 cells' matched $\alpha$ (still $\alpha{=}2$ throughout). Nothing here has been
written into the actual paper file.

\section{Table 3 recreation (EE-D-interval utility gain, LaMP-1 and LaMP-4)}

Unlike Tables 2 and 4, Table 3 assigns each individual \emph{query} to one of five
EE-D intervals based on that query's own EE-D under a given PL $\alpha$, then
reports the mean utility gain (vs.\ the deterministic baseline) of all queries
landing in that bin. Swapping in $N{=}100$ EE-D therefore changes which bin each
query falls into, not just a summary value --- this recomputes per-query EE-D at
$N{=}100$ for all four PL $\alpha\in\{1,2,4,8\}$ across all 8 (task, generator,
ranker) cells, then re-bins and re-aggregates utility gain (utility itself, and
which queries exist, is completely unchanged --- still the real $N{=}10$ generation
runs). The ``Baseline'' column (deterministic EU$_{\text{norm}}$) is unaffected by
any of this and is reproduced as-is. The source paper's own numbers (``Paper''
column) are of course also unaffected.
